# Практическая работа №4. Условные конструкции

## Цель работы
Изучить работу условных операторов `if`, `else if`, `else`, логических операторов (`&&`, `||`, `!`), а также научиться использовать `switch` и тернарный оператор `?:`.

## ПР4. Ответы на контрольные вопросы

### 1. В чём разница между одиночным if и конструкцией if-else?
Одиночный `if` проверяет условие и выполняет блок кода, только если оно истинно (`true`). Если условие ложно, программа просто идёт дальше. Конструкция `if-else` даёт два варианта развития: если условие истинно — выполняется первый блок, если ложно (`false`) — выполняется блок внутри `else`.

### 2. Как работает цепочка else if и сколько веток в ней может выполниться за один запуск программы?
Условия проверяются по очереди сверху вниз. Как только находится первое истинное условие, выполняется его блок кода, а все остальные ветки ниже пропускаются. Поэтому за один проход может выполниться максимум **одна** ветка (или ни одной, если нет блока `else`).

### 3. Зачем нужен оператор switch, если его всегда можно заменить цепочкой if-else if?
`switch` удобнее и читаемее, когда одну и ту же переменную нужно сравнить с несколькими конкретными значениями (например, с оценками от 2 до 5 или номерами месяцев). Код получается короче, без постоянного повторения `x == ...`.

### 4. Что такое тернарный оператор и в каких ситуациях его удобно использовать?
Тернарный оператор (`условие ? значение1 : значение2`) — это короткая запись простого `if-else` в одну строчку. Его удобно использовать, когда нужно быстро выбрать одно из двух значений и сразу записать его в переменную или вывести на экран.

### 5. В чём разница между логическим И (&&) и логическим ИЛИ (||) при проверке составных условий?
- `&&` (И) возвращает `true`, только если **оба** условия истинны. Если хотя бы одно ложно — результат будет `false`.
- `||` (ИЛИ) возвращает `true`, если истинно **хотя бы одно** условие. `false` получится только тогда, когда ложны оба условия.

### 6. Зачем в конце каждой ветки case в операторе switch обязательно писать break?
`break` завершает работу `switch` и не даёт программе случайно перейти к выполнению следующей ветки `case`. В C# «проваливание» из одного `case` в другой с кодом запрещено — без `break` программа просто не скомпилируется.
